# WIL (XHAW5112)
## Task 1: Phase 2 & Phase 3 Submission Checklist

> **Before You Submit**
>
> Use this checklist to make sure that your group has completed all required components before submitting.

- [ ] We have formed a group of 3 members (or have an approved variation from the lecturer).
- [ ] We have selected a Team Leader.
- [ ] Additional roles have been assigned according to the Team Contract.
- [ ] Every member understands their responsibilities.
- [ ] All group members have access to the group's communication platform and GitHub repository.

---

# PHASE 2 CHECKLIST — 10 Marks

## Group Information

- [ ] The assignment template has been used.
- [ ] Full names of all group members are included.
- [ ] Student numbers of all group members are included.
- [ ] GitHub usernames for all members are included and clearly matched to each student.

## Roles and Responsibilities

- [ ] The Team Leader has been identified.
- [ ] Additional roles have been assigned where required.
- [ ] Roles are clearly explained and linked to specific students.

## Task Allocation

- [ ] Every group member has been assigned specific tasks.
- [ ] Responsibilities cover Task 1, Task 2 and Task 3.
- [ ] Work has been distributed fairly.
- [ ] It is clear who is responsible for:

| Responsibility | Assigned To |
|---|---|
| Wireframes | Everyone |
| Mobile App Development | Code and Test |
| Website Development | Code and Test |
| Documentation | Steward |
| GitHub Management | Technical Integration |
| Presentation Preparation | Everyone |

- [ ] No member has been assigned vague responsibilities such as "help with coding" or "assist the group."

## Group Agreement

- [ ] The Group Agreement has been completed.
- [ ] A soft copy of the Team Contract is attached to the submission.
- [ ] All required sections have been completed.
- [ ] All members have signed the agreement.
- [ ] The Group Agreement has been saved as a PDF.
- [ ] The Group Agreement has been submitted separately if required.

# PHASE 3 CHECKLIST — 55 Marks

## 1. Design Decision Report

### Scenario Selection

- [ ] The group has selected **ONE final scenario**.
- [ ] If members selected different scenarios in Phase 1, the final decision is explained.
- [ ] Reasons for selecting the final scenario are clearly provided.

### Logo Selection

- [ ] The final logo is shown.
- [ ] The group explains whose logo was selected.
- [ ] If the logo combines multiple ideas, this is explained.
- [ ] The logo supports the chosen business.

### Colour Palette Selection

- [ ] The final colour palette is shown.
- [ ] Reasons for selecting the colours are explained.
- [ ] The colours support the business identity.
- [ ] The chosen palette can realistically be used in both the website and mobile application.

### Evidence of Decision Making

- [ ] Screenshots from individual Phase 1 submissions are included.
- [ ] Screenshots are clearly labelled.
- [ ] It is obvious whose work was selected.
- [ ] It is obvious what was accepted, rejected or combined.
- [ ] Explanations accompany all screenshots.

# 2. Research Section — 15 Marks

> The rubric expects research covering **four key areas**. Navigation research should address both the website and mobile application where applicable.

## Navigation

- [ ] Research on website navigation has been completed.
- [ ] Research on mobile application navigation has been completed.
- [ ] Findings are summarised.
- [ ] The group explains how navigation ideas will be used in the project.

## Screen Layout

- [ ] Research on effective screen layouts has been completed.
- [ ] Examples are discussed.
- [ ] Findings are linked to the project.

## Responsive Design

- [ ] Responsive design is explained.
- [ ] The importance of designing for different screen sizes is discussed.
- [ ] The concept is linked to the project.

## User Interface Design

- [ ] UI design principles have been researched.
- [ ] Research includes usability and user experience considerations.
- [ ] The team explains how the research will influence the final design.

## Referencing

- [ ] References are included.
- [ ] In-text citations are included where required.
- [ ] A reference list is included.
- [ ] Sources are academic or professional.

# Most Common Reasons Students Will Lose Marks

> **Check these carefully before submitting.**

- [ ] No explanation of **WHY** the final logo, scenario and colour palette were chosen.
- [ ] Screenshots included without labels.
- [ ] Research section contains copied content with no references.
- [ ] Research does not cover all four required areas.
- [ ] Infrastructure simply lists tools without explaining their purpose.
- [ ] Low-fidelity wireframes look like high-fidelity wireframes.
- [ ] Missing Figma link.
- [ ] Wireframes do not include all 12 required screens.
- [ ] Tasks are assigned only for Task 1 and not for the remainder of the project.
- [ ] GitHub usernames are missing or incorrect.

---

# How Task 1 Connects to Task 2 and Task 3

Students should understand the following progression:

## Task 1 — Planning & Design

**Form team → Assign responsibilities → Select logo → Select colour palette → Conduct research → Create low-fidelity wireframes**

↓

## Task 2 — Build What You Planned

**Convert low-fidelity wireframes into high-fidelity wireframes → Finalise all screens → Apply colours, images and branding → Develop the mobile application → Start website development → Work through GitHub continuously**

↓

## Task 3 — Complete & Present

**Finish website → Add CSS and JavaScript → Publish website → Present project → Submit final portfolio and reflections**

---

# Final Message

> **If your decisions are weak in Task 1, your wireframes will be weak in Task 2, and your application and website will be weak in Task 3.**
>
> Task 1 is not a small administrative task. **It is the blueprint for the entire project.**
