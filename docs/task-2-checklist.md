### Pull Requests

✓ Pull Requests created

✓ Pull Requests approved

### Commit History

✓ Frequent commits  
✓ Commits spread across team  
✓ Commit messages are meaningful  

Examples:

✓ Added fee calculator functionality  
✓ Updated home screen navigation  
✓ Added contact page content  

Avoid:

✗ changes  
✗ update  
✗ stuff  

----------

### Golden Rule Check

The workflow guide clearly states:

> Keep main stable and perform development work on feature branches before using Pull Requests to merge into main.

Ask:

✓ Was development completed on branches?  
✓ Was main used as the stable version?  
✓ Were Pull Requests used?

### The Message You Need To Hear

> **Task 2 is not simply about producing a mobile application. It is about demonstrating professional software engineering practice. The mobile app, website repository, GitHub history, activity logs, meeting minutes, pull requests, commits, code quality, documentation, references and presentation should all tell the same story. If the assessor opens any one piece of evidence, it should support and reinforce every other piece of evidence in the submission.**
