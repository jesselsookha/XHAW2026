# XHAW5112 Work Integrated Learning (WIL)

Welcome to the official XHAW5112 Work Integrated Learning project repository.

This repository contains the planning, governance and workbook resources that will guide you through the full project lifecycle for the semester.

The repository has been designed to support you from the earliest stages of project discovery through to final presentation, portfolio submission and professional reflection.

While the official WIL Module Manual remains the primary academic and assessment document for this module, the resources contained in this repository provide the practical tools, templates, guidance and workbooks required to successfully complete your project.

---

# The XHAW5112 Project Journey

The project follows a structured development process similar to what students may experience in industry.

```text
IDEA
  ↓
PROPOSAL
  ↓
TEAM FORMATION
  ↓
DESIGN
  ↓
DEVELOPMENT
  ↓
TESTING
  ↓
PRESENTATION
  ↓
REFLECTION
```

Each workbook and supporting document has been created to support a specific stage of this journey.

Students should follow the sequence carefully and avoid jumping ahead unnecessarily.

# Understanding the Repository

The repository is divided into three main categories:

## 1. Administrative Documents

These documents support project administration and evidence collection throughout the semester.

### Semester Timeline

Use this document to:

- Track assessment milestones.
- Monitor important deadlines.
- Plan project activities.
- Coordinate group work.

### Activity Log / Timesheet

Use this document to:

- Record individual contributions.
- Track project activities.
- Provide evidence of participation.
- Support lecturer reviews and evaluations.

This document should be updated regularly throughout the semester.

---

## 2. Governance Documents

These documents help your team operate professionally.

### Team Contract

**When is it used?**

Week 1 of group formation.

**Purpose**

The Team Contract is a formal agreement between team members.

It establishes:

- Communication expectations
- Team roles
- Attendance expectations
- Accountability standards
- Escalation procedures
- Professional conduct requirements

All team members are expected to sign the contract.

The contract should be completed once and retained as project evidence.

---

### Team Operations Handbook

**When is it used?**

Throughout the entire semester.

**Purpose**

The Team Operations Handbook is the operational guide for your team.

It explains:

- How teams should function
- How meetings should be conducted
- How decisions should be recorded
- How actions should be tracked
- How issues should be escalated
- How professional project records should be maintained

Think of this document as your team's operating manual.

Whenever your team is uncertain about meetings, communication, responsibilities or project governance, consult the Team Operations Handbook.

# Understanding the Workbooks

The workbooks guide the actual project lifecycle.

Each workbook represents a major project stage.

---

# Workbook 1
## Project Discovery and Proposal Development

### Project Stage

```text
IDEA → PROPOSAL
```

### Individual Activity

Workbook 1 is completed individually.

### Purpose

In this workbook you will:

- Explore project scenarios
- Analyse opportunities
- Evaluate alternatives
- Apply user-centred design principles
- Develop brand concepts
- Create logo ideas
- Plan colour palettes
- Explore website requirements
- Explore mobile application requirements

### Deliverables

By the end of Workbook 1 you should have:

- A preferred project scenario
- Initial research findings
- Brand identity concepts
- User analysis
- Website planning ideas
- Mobile application planning ideas

These outputs become the foundation of group discussions in Workbook 2.

---

# Workbook 2
## Group Formation and Solution Design

### Project Stage

```text
TEAM FORMATION → DESIGN
```

### Group Activity

Workbook 2 is completed as a group.

### Purpose

Your team will:

- Form project groups
- Allocate project roles
- Review Workbook 1 proposals
- Compare project ideas
- Select the final scenario
- Select a final logo
- Select a final colour palette
- Conduct design research
- Plan project infrastructure
- Create information architecture
- Develop low-fidelity wireframes

### Important Note

Workbook 2 works alongside the Team Operations Handbook.

The Team Operations Handbook explains how professional teams operate.

Workbook 2 records the decisions your team makes.

Together, these documents provide evidence of both teamwork and project planning.

### Deliverables

By the end of Workbook 2 you should have:

- A functioning project team
- Assigned roles
- Selected project scenario
- Approved brand identity
- Approved colour palette
- Project infrastructure plan
- Site map
- User journeys
- Low-fidelity wireframes

These outputs prepare your team for development.

---

# Workbook 3
## Development and Implementation

### Project Stage

```text
DEVELOPMENT → TESTING
```

### Group Activity

Workbook 3 is completed throughout development.

### Purpose

Your team will:

- Plan development activities
- Track project progress
- Monitor implementation
- Record testing activities
- Validate requirements
- Monitor GitHub activity
- Track project milestones
- Prepare deployment evidence

### Relationship to the Team Operations Handbook

Workbook 3 tracks what is being developed.

The Team Operations Handbook records how the team is operating.

Teams should continue using the handbook throughout development to:

- Conduct meetings
- Record decisions
- Monitor actions
- Manage issues
- Complete integration reviews

### Deliverables

By the end of Workbook 3 you should have:

- Completed mobile application
- Completed website
- Testing evidence
- GitHub evidence
- Deployment evidence
- Development reflections

These outputs prepare the team for final presentation.

---

# Workbook 4
## Presentation, Reflection and Portfolio

### Project Stage

```text
PRESENTATION → REFLECTION
```

### Group Activity

Workbook 4 is completed during project finalisation.

### Purpose

Your team will:

- Reflect on the project journey
- Prepare presentation materials
- Plan demonstrations
- Prepare presentation scripts
- Assemble portfolio evidence
- Conduct peer evaluations
- Complete professional reflections

### Relationship to the Team Operations Handbook

Although development activities are largely complete at this stage, teams should continue using the Team Operations Handbook to:

- Archive evidence
- Record final decisions
- Maintain documentation
- Capture lessons learned
- Support professional reflection

### Deliverables

By the end of Workbook 4 you should have:

- A completed presentation
- Demonstration plan
- Portfolio evidence
- Reflection evidence
- Submission readiness checks
- Final project documentation

# Recommended Student Workflow

Students should follow this sequence:

```text
1. Read the WIL Module Manual
            ↓
2. Review the Semester Timeline
            ↓
3. Complete Workbook 1
            ↓
4. Form Groups
            ↓
5. Complete Team Contract
            ↓
6. Begin Using the Team Operations Handbook
            ↓
7. Complete Workbook 2
            ↓
8. Complete Workbook 3
            ↓
9. Complete Workbook 4
            ↓
10. Submit Portfolio and Present Project
```

Following this sequence will ensure that project planning, governance, development and evidence collection occur in a structured and professional manner.
